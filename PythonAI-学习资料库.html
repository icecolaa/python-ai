配置 API Key（必读）#

不要把密钥写死在代码里。 所有示例都从环境变量读取，请先在系统里配置：

当前示例（阶跃星辰）使用 STEP_API_KEY，按你实际接入的平台设置对应变量即可：

# macOS / Linux
export STEP_API_KEY="你的密钥"
export DASHSCOPE_API_KEY="你的密钥"      # 阿里云百炼
export SILICONFLOW_API_KEY="你的密钥"    # 硅基流动

# Windows PowerShell
$env:STEP_API_KEY="你的密钥"
$env:DASHSCOPE_API_KEY="你的密钥"
$env:SILICONFLOW_API_KEY="你的密钥"

也可以在仓库根目录新建 .env 文件（已被 .gitignore 忽略，不会提交）：

1.3 大语言模型原理#

核心思想：把人类语言转化为数学向量，通过向量运算来理解和生成语言。

分步理解：

  1. 词向量化：每个词被表示为一个多维向量（一组数字）。例如“中国”是一个向量，“美国”是另一个向量。

语义运算：E(美国) - E(中国) 得到的向量表示两个国家的差异。那么：

  1. E(汉堡) + [E(美国) - E(中国)] ≈ E(肉夹馍)

正是这种向量运算能力，让模型能进行类比推理。

  1. 上下文预测：给定上文，计算下文最可能出现的词。模型本质上是一个“完形填空机器”，只是在海量训练后，这种能力泛化为了通用智能。
  2. 泛化涌现：当模型和数据规模足够大时，模型不仅会填词，还能理解、推理、分析生活中的大部分问题——这被称为泛化能力。

2. 大模型应用开发：是什么？怎么做？#

2.1 什么是大模型应用？#

大模型应用是将大模型的“思考”能力与传统程序的“执行”能力相结合开发的软件。

能力 传统程序 大模型
擅长 规则明确的计算、固定流程、精确控制 自然语言理解、模糊问题回答、创作
不擅长 理解自然语言、处理模糊需求 精确计算、稳定可预测的结果

大模型应用的本质：大模型负责“思考”，传统程序负责“行动”。

重要认知：你日常使用的通义千问、豆包、ChatGPT等，都是基于大模型开发的应用，而非大模型本身。它们额外实现了会话记忆、联网搜索、文件上传等功能。

5.1 阶段一：单次对话机器人#

目标：发送一条消息，获取大模型的一次回复，验证API调用链路通畅。

# 1. 导入必要的库
from openai import OpenAI

# 2. 初始化大模型客户端
# 以百度AI Studio兼容接口为例
client = OpenAI(
    api_key="你的API_Key",                          # 替换为你的真实Key
    base_url="https://aistudio.baidu.com/llm/lmapi/v3"  # 百度AI Studio接口
)

# 3. 调用API获取回复
response = client.chat.completions.create(
    model="ernie-4.5-0.3b",                         # 模型名称（百度文心轻量版，免费额度充足）
    messages=[
        {"role": "system", "content": "你是一个友好的AI助手，回答简洁明了"},  # 系统指令
        {"role": "user", "content": "请介绍一下自己，一句话即可"}              # 用户输入
    ]
)

# 4. 解析并输出结果
ai_reply = response.choices[0].message.content
print(f"AI助手：{ai_reply}")

代码要点解析：

组件 作用
api_key 身份凭证，证明你有权调用模型
base_url 大模型服务的访问地址
model 指定使用哪个模型（不同模型能力不同）
messages 对话上下文，system定义AI角色，user是用户输入

通常消息的角色有三种：

角色 描述 示例
system 优先于user指令之前的指令，也就是给大模型设定角色和任务背景的系统指令 你是一个乐于助人的编程助手，你以小团团的风格来回答用户的问题。
user 终端用户输入的指令（类似于你在ChatGPT聊天框输入的内容） 写一首关于Java编程的诗
assistant 由大模型生成的消息，可能是上一轮对话生成的结果 注意，用户可能与模型产生多轮对话，每轮对话模型都会生成不同结果。

其中System类型的消息非常重要！影响了后续AI会话的行为模式。

比如，我们会发现，当我们询问这些AI对话产品“你是谁”这个问题的时候，每一个AI的回答都不一样，这是怎么回事呢？

5.2 阶段二：多轮对话机器人（带记忆功能）#

这里还有一个问题：

大模型的API接口是"无状态"的，服务端不会记录用户请求的上下文。因此我们调用API接口与大模型对话时，每一次对话信息都不会保留，多次对话之间都是独立的，没有关联的。

因此大模型并不知道之前的聊天历史，也就是说大模型是没有记忆的。

解决方法：把历史消息都放入Messages中，形成一个数组，实现连续交互，让AI能记住之前的对话内容。

from openai import OpenAI

# 1. 初始化客户端
client = OpenAI(
    api_key="你的API_Key",
    base_url="https://aistudio.baidu.com/llm/lmapi/v3"
)

# 2. 对话历史（AI的“记忆”）
messages = []

print("=== AI聊天机器人已启动 ===")
print("输入'退出'结束对话\n")

# 3. 循环对话
while True:
    # 获取用户输入
    user_input = input("你：")

    # 判断退出
    if user_input == "退出":
        print("AI：再见！")
        break

    # 把用户消息加入记忆
    messages.append({"role": "user", "content": user_input})

    # 调用大模型
    response = client.chat.completions.create(
        model="qwen-turbo",
        messages=messages
    )

    # 获取回复并输出
    reply = response.choices[0].message.content
    print(f"AI：{reply}\n")

    # 把AI回复也加入记忆
    messages.append({"role": "assistant", "content": reply})

多轮对话原理：

  • messages列表存储了完整的对话历史
  • 每次调用API时，将整个历史发送给模型
  • 模型基于全部历史生成回复，从而“记住”前面的内容

6. 一些常见的符号#

模型参数大小#

  • K = 千
  • M = 百万
  • B = 十亿（最常用，如7B = 70亿参数）
  • T = 万亿

上下文窗口#

  • 8K / 32K / 128K 中的 K = 千字符
  • 代表AI一次能“记住”多少文字
  • 1个汉字 ≈ 2个Token

一句话分清#

  • B：模型聪不聪明（参数量）
  • K：记性好不好（上下文窗口长度）

模型命名规则#

格式：系列名 + 版本号 + 参数量 + 用途标签

示例：

  • Qwen2.5-7B-Instruct：Qwen系列，2.5版本，70亿参数，对话指令专用
  • Qwen-turbo：Qwen极速特供版（云端不标参数）

5. 虚拟环境管理——解决环境冲突的银弹#

痛点：项目 A 要用 Django 3.2，项目 B 要用 Django 4.2，直接装系统全局会冲突。虚拟环境为每个项目创建独立的 Python 解释器环境，各自拥有独立的包，互不干扰。

5.1 使用 Python 内置 venv（轻量快捷）#

# 在项目根目录打开终端
python -m venv myenv          # 创建名为 myenv 的虚拟环境
# 激活（Windows）
myenv\Scripts\activate
# 激活（macOS/Linux）
source myenv/bin/activate
# 现在命令行前缀会显示 (myenv)，用 pip 安装的包只在此环境生效
pip install numpy
# 退出虚拟环境
deactivate

5.2 使用 Conda（数据科学与多语言环境首选）#

Conda 可管理 Python 自身版本以及 C 扩展包，尤其适合 AI 领域。

  1. 下载并安装 Miniconda（体积小，仅包含 conda + Python）。
  2. 安装时务必勾选“Add to PATH”（或安装后手动配置环境变量：将 D:\conda 及 D:\conda\Scripts 加入系统 Path）。
  3. 验证：打开新终端，输入 conda --version 显示版本即成功。
  4. 基本命令：
conda create -n aicourse python=3.11   # 创建指定 Python 版本的环境
conda activate aicourse                # 激活环境
pip install numpy pandas               # 安装科学计算包
conda deactivate                       # 退出
conda env list                         # 查看所有环境
conda env remove -n aicourse           # 删除环境

注意：激活 conda 环境后，pip 和 conda 安装的包都会进入该环境，互不影响。

5.3 理解系统 Python 与环境 Python#

  • 系统 Python：安装在操作系统 Path 中的解释器，用于全局调用。

Python 内置四种数字类型：int（整数）、float（浮点数）、bool（布尔值）、complex（复数）。其中前三种最常用。

1.1 整数 int：无限大，有小整数池#

  • Python 3 中整数没有大小限制，理论上可以表达任意大的数。
  • 小整数池：[-5, 256] 范围内的整数，解释器会预先创建并复用，以优化内存。因此不同变量赋相同小整数时，可能指向同一对象。

1.2 浮点数 float：精度陷阱与正确比较#

2.2 实战：猜数字游戏（串联 while、match、break）#

import random

# 随机出一个目标值
target = random.randint(1, 100)
# 限制最多7次机会
attempts = 0
max_attempts = 7

while attempts < max_attempts:
    guess = int(input(f"猜 1-100（剩余 {max_attempts - attempts} 次）: "))

    match (guess > target, guess < target):
        case (True, False):
            print("大了")
        case (False, True):
            print("小了")
        case (False, False):
            print("恭喜猜对了！")
            break       # 结束while循环，不再猜数了

    attempts += 1       # 猜数的已使用次数 + 1
else:  # 循环自然结束（没用 break），说明次数用尽
    print(f"机会用完啦，答案是 {target}")

4. 推导式 —— 列表/集合/字典的快速生成#

推导式是 Python 的标志性语法糖，让数据转换代码一行搞定。

odds = [i for i in range(1, 11) if i % 2 == 1]

装饰器是 Python 中非常强大的特性，它可以让你在不修改原函数代码的情况下，给它增加额外的功能（如计时、日志、权限校验）。在大模型应用中，它常用于记录API调用耗时、缓存结果、重试等场景。

4.1 通用装饰器模板#

import time
import functools

def timer(func):
    """一个计时装饰器，可以装饰在任何函数上"""
    @functools.wraps(func)  # 保留原函数的函数名、文档等元信息
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = func(*args, **kwargs)  # 执行原始函数
        cost = time.perf_counter() - start
        print(f"[计时] {func.__name__} 耗时: {cost:.4f} 秒")
        return result
    return wrapper

# 使用装饰器
@timer
def process_data():
    time.sleep(1.5)     # 模拟函数的执行耗时
    return "处理完成"

# 调用时自动计时
process_data()

# 使用装饰器
@timer
def baize():
    print("我是白泽，正在测试装饰器")
    print("看一下 计时器装饰器 的使用")

4.2 带参数的装饰器#

def retry(max_attempts=3):
    """一个带参数的重试装饰器"""
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            for attempt in range(max_attempts):
                try:
                    return func(*args, **kwargs)
                except Exception as e:
                    print(f"重试 {attempt+1}/{max_attempts} 失败: {e}")
            raise Exception(f"函数 {func.__name__} 重试 {max_attempts} 次后仍失败")
        return wrapper
    return decorator

# 使用带参数的装饰器
import random
@retry(max_attempts=5)
def unstable_network_call():
    if random.random() < 0.7:
        raise ConnectionError("网络抖动")
    return "数据获取成功"

print(unstable_network_call())

4.3 实战：缓存装饰器#

利用装饰器实现一个简单的缓存功能，避免重复计算，这在处理一些耗时运算时非常有用。

def cache(func):
    _cache = {}  # 用来存结果
    @functools.wraps(func)
    def wrapper(*args):
        if args not in _cache:
            _cache[args] = func(*args)  # 第一次算，存起来
        return _cache[args]             # 之后直接取
    return wrapper

@cache
def expensive_computation(n):
    print(f"正在进行耗时为 {n} 秒的计算...")
    time.sleep(n)
    return n * 2

print(expensive_computation(2))  # 会等待
print(expensive_computation(3))  # 会等待
print(expensive_computation(2))  # 瞬间返回，因为命中了缓存
print(expensive_computation(3))  # 瞬间返回，因为命中了缓存

class Account:
    def __init__(self, acc_no, name, balance=0):
        self.acc_no = acc_no
        self.name = name
        self.__balance = balance

    @property
    def balance(self):
        return self.__balance

    def deposit(self, amount):
        if amount > 0:
            self.__balance += amount
            print(f"入账 {amount} 元，余额 {self.__balance} 元")
        else:
            print("存款金额必须为正数")

    def withdraw(self, amount):
        if 0 < amount <= self.__balance:
            self.__balance -= amount
            print(f"取出 {amount} 元，余额 {self.__balance} 元")
        else:
            print("余额不足或金额无效")

驱动问题：我们要开发一个高性能的大模型API调用后端。它需要同时处理成百上千个用户的请求，但大部分时间其实是在等待网络响应。如果我们每次请求都创建一个新线程，内存和切换开销会非常大。协程（Coroutine）是一种更高效的方案：它能在一个线程内并发处理海量I/O任务，是现代化Web框架（如FastAPI）的核心技术。本节将掌握Python协程的核心用法。

1. 为什么需要协程？#

我们来看一个常见的场景：你的程序需要同时向3个不同的URL发送请求，并汇总结果。

  • 传统方式：逐个请求，总耗时是3次请求的时间之和。
  • 协程方式：同时发起3个请求，在等待网络响应时（I/O阻塞），程序会去执行其他任务，总耗时接近最慢的那一次请求。

协程就是这样一个在单线程内处理并发的利器。它由我们程序员自己决定何时“暂停”和“切换”任务，而不是被操作系统强制打断，因此也被称为协作式多任务。

它最大的优势是极轻量，一个程序里可以同时运行成千上万个协程，而内存和CPU开销极小。非常适合I/O密集型任务（网络、文件读写、数据库操作）。

2. 核心语法：async/await#

要使用协程，必须掌握两个新的Python关键字和事件循环。

2.1 定义协程函数：async def#

与普通函数不同，协程函数调用后不会立即执行，而是返回一个协程对象，必须交给事件循环去运行。

import asyncio

# 定义一个协程函数
async def hello():
    print("Hello")
    await asyncio.sleep(1) # 模拟耗时操作，交出控制权
    print("World")

# 直接调用不会执行
h = hello()
print(type(h)) # <class 'coroutine'>

# # 必须用 asyncio.run() 来启动事件循环并执行
# asyncio.run(hello())

2.2 等待协程：await#

await 关键字只能在 async def 定义的函数内部使用。它的作用是：

  1. 暂停当前协程。
  2. 等待一个可等待对象（另一个协程、Task等）完成。
  3. 交出控制权给事件循环，让它去执行其他协程。
import asyncio
import time

async def say_after(delay, what):
    # asyncio.sleep 是一个协程，会在这里交出控制权
    await asyncio.sleep(delay)
    print(f"{time.strftime('%X')}: {what}")

async def main():
    print(f"开始 {time.strftime('%X')}")
    # 这里虽然写了两个await，但它们是顺序执行的，总耗时 2+1=3秒
    await say_after(2, 'world')
    await say_after(1, 'hello')
    print(f"结束 {time.strftime('%X')}")

asyncio.run(main())

输出：

开始 14:20:05
14:20:07: world
14:20:08: hello
结束 14:20:08

如何让它们真正并发执行？ 这就要用到“任务”。

3. 并发执行：创建任务（Task）#

要同时运行多个协程，你需要把它们包装成任务（Task），然后注册到事件循环中。

3.1 推荐方式：asyncio.gather()#

这是最常用的并发方式，能同时启动多个协程，并等待它们全部完成，返回一个包含所有结果的列表。

import asyncio
import time

async def worker(name, delay):
    print(f"{name} 开始")
    await asyncio.sleep(delay)
    print(f"{name} 完成")
    return f"结果_{name}"

async def main():
    # 并发执行worker("A")和worker("B")，总耗时取最长的时间（2秒）
    results = await asyncio.gather(
        worker("A", 2),
        worker("B", 1)
    )
    print(results)  # ['结果_A', '结果_B']

print(f"开始 {time.strftime('%X')}")
asyncio.run(main())
print(f"结束 {time.strftime('%X')}")

3.2 更精细的控制：asyncio.create_task()#

create_task() 会立即调度一个协程，并返回一个 Task 对象。之后你可以单独 await 它的结果，或者取消它。

import asyncio
import time

async def worker(name, delay):
    print(f"{name} 开始")
    await asyncio.sleep(delay)
    print(f"{name} 完成")
    return f"结果_{name}"

async def main():
    # 将协程包装成任务，立即开始调度
    task_a = asyncio.create_task(worker("A", 2))
    task_b = asyncio.create_task(worker("B", 1))

    # 在等待A和B的同时，主协程可以继续做其他事
    print("主协程在干别的事...")

    # 最后再等待任务完成并获取结果
    result_a = await task_a
    result_b = await task_b
    print(result_a, result_b)

asyncio.run(main())

4. 协程同步机制：信号量（Semaphore）#

虽然协程是单线程的，但在await处切换时，如果有共享资源（如全局计数器）或者需要限制并发数量（如爬虫频率），就需要同步工具。其中最常用的是信号量 Semaphore。

信号量 asyncio.Semaphore#

它像一个“令牌桶”，可以限制同时访问某个资源的协程数量。这对于控制API调用频率、限制数据库连接数等场景至关重要。

import asyncio

# 创建一个信号量，最多允许2个协程同时运行
sem = asyncio.Semaphore(2)

async def limited_task(name):
    # async with sem 会在进入时获取令牌，退出时归还令牌
    async with sem:
        print(f"{name} 获得许可，开始执行")
        await asyncio.sleep(2)
        print(f"{name} 执行完毕，归还许可")

async def main():
    # 同时启动5个任务，但因为信号量限制，同时最多只有2个在执行
    await asyncio.gather(
        limited_task("任务1"),
        limited_task("任务2"),
        limited_task("任务3"),
        limited_task("任务4"),
        limited_task("任务5")
    )

asyncio.run(main())

你会观察到：任务1和2先获得许可，2秒后它们完成，任务3和4获得许可，最后是任务5。

5. 实战：高性能异步API客户端 (aiohttp)#

协程最强大的应用场景就是编写高性能的网络客户端。我们以 aiohttp 库为例，演示如何用协程并发请求多个URL。
（pip install aiohttp）

import asyncio
import aiohttp
import time

# 异步请求函数，接受session、url和信号量
async def fetch(session, url, sem):
    async with sem: # 使用信号量限制并发
        try:
            # 发起异步GET请求
            async with session.get(url, timeout=5) as resp:
                text = await resp.text()
                print(f"✅ {url} 状态: {resp.status}, 长度: {len(text)}")
                return len(text)
        except Exception as e:
            print(f"❌ {url} 异常: {e}")
            return 0

async def main():
    urls = [
        "https://httpbin.org/delay/1",
        "https://httpbin.org/delay/2",
        "https://httpbin.org/json",
    ]
    # 限制最多3个并发请求
    sem = asyncio.Semaphore(3)

    start = time.time()
    # 创建一个客户端会话（session），可复用底层TCP连接，性能更高
    async with aiohttp.ClientSession() as session:
        # 为每个URL创建一个fetch协程
        tasks = [fetch(session, url, sem) for url in urls]
        # 并发执行所有任务
        results = await asyncio.gather(*tasks, return_exceptions=True)

    print(f"总耗时: {time.time() - start:.2f} 秒")
    print("各页面大小:", results)

asyncio.run(main())

关键点：

  • aiohttp.ClientSession()：复用连接，提升性能。
  • asyncio.gather(*tasks)：* 用于将列表解包为多个参数。
  • return_exceptions=True：某个任务失败不影响其他任务。

6. 优质练习与答案#

练习1 – 协程超时控制
用 asyncio.wait_for 为一个慢速任务设置超时时间。

import asyncio

async def slow_task():
    await asyncio.sleep(5)
    return "慢任务完成"

async def main():
    try:
        result = await asyncio.wait_for(slow_task(), timeout=2)
        print(result)
    except asyncio.TimeoutError:
        print("任务超时，已取消！")

asyncio.run(main())

练习2 – 限制并发的批量下载器
编写一个函数 batch_download(urls, max_concurrent=2)，它使用信号量限制并发数，并发地请求所有URL并打印状态码。

import asyncio
import aiohttp

async def fetch_status(session, url, sem):
    async with sem:
        async with session.get(url) as resp:
            return url, resp.status

async def batch_download(urls, max_concurrent=2):
    sem = asyncio.Semaphore(max_concurrent)
    async with aiohttp.ClientSession() as session:
        tasks = [fetch_status(session, url, sem) for url in urls]
        results = await asyncio.gather(*tasks)
        for url, status in results:
            print(f"{url} -> 状态码: {status}")

# 测试
urls = ["https://httpbin.org/status/200"] * 4
asyncio.run(batch_download(urls, max_concurrent=2))
