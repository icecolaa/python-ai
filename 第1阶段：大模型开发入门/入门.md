### 二、课程定位：从零基础到企业级大模型开发工程师

本课程专为零基础 / 转行者打造，以「实战驱动、全栈覆盖、岗位匹配」为核心，从 Python 基础入门，到 NLP 核心、大模型微调、Agent 智能体、RAG 检索增强、多模态开发、具身智能前沿，完整覆盖大模型应用开发全链路技术，培养企业紧缺的全栈式大模型开发人才，精准匹配大模型开发、NLP、多模态三大热门岗位需求。

✅ **全栈技术体系**：覆盖 Python 基础→数据处理→机器学习→深度学习→Transformer→大模型微调→Agent→RAG→多模态→具身智能，从入门到进阶一站式掌握

## 1. AI发展简史与大模型原理

### 1.1 AI发展的四大阶段

| **阶段** | **时期** | **核心思想** | **代表成就** |
| --- | --- | --- | --- |
| **规则与符号** | 1950s-1970s | 用预设的逻辑和符号规则复刻智能 | 象棋对弈、定理证明 |
| **统计与学习** | 1980s-1990s | 从数据中自行发现规律（机器学习） | 垃圾邮件过滤、推荐系统 |
| **深度学习** | 2000s-2010s | 深层神经网络自动提取多层特征 | 人脸识别、语音助手 |
| **大模型革命** | 2020s至今 | 通用认知智能，通过对话完成复杂任务 | ChatGPT、DeepSeek、通义千问 |

### 1.2 智能产生的三大要素

大模型之所以能产生“智能”，依赖三个核心支柱：

| **要素** | **作用** | **比喻** |
| --- | --- | --- |
| **模型算法** | AI的“大脑”，神经网络架构 | 大脑的结构决定了智力上限 |
| **海量数据** | AI的“知识”，训练材料 | 读的书越多，见识越广 |
| **超级算力** | AI的“能量”，计算资源 | 需要足够的能量才能运转 |

**直观理解**：算法决定了AI的学习能力上限，数据提供了学习的内容，算力则保证学习能够实际完成。三者缺一不可。

### 1.3 大语言模型原理

**核心思想**：把人类语言转化为数学向量，通过向量运算来理解和生成语言。

**分步理解**：

1. **词向量化**：每个词被表示为一个多维向量（一组数字）。例如“中国”是一个向量，“美国”是另一个向量。

**语义运算**：<span style="background-color:#f7f6f3">E(美国) - E(中国)</span> 得到的向量表示两个国家的差异。那么：

1. E(汉堡) + \[E(美国) - E(中国)\] ≈ E(肉夹馍)

正是这种向量运算能力，让模型能进行类比推理。

1. **上下文预测**：给定上文，计算下文最可能出现的词。模型本质上是一个“完形填空机器”，只是在海量训练后，这种能力泛化为了通用智能。
2. **泛化涌现**：当模型和数据规模足够大时，模型不仅会填词，还能理解、推理、分析生活中的大部分问题——这被称为**泛化**能力。

## 2. 大模型应用开发：是什么？怎么做？

### 2.1 什么是大模型应用？

**大模型应用**是将**大模型**的“思考”能力与**传统程序**的“执行”能力相结合开发的软件。

| **能力** | **传统程序** | **大模型** |
| --- | --- | --- |
| **擅长** | 规则明确的计算、固定流程、精确控制 | 自然语言理解、模糊问题回答、创作 |
| **不擅长** | 理解自然语言、处理模糊需求 | 精确计算、稳定可预测的结果 |

**大模型应用的本质**：**大模型负责“思考”，传统程序负责“行动”**。

**重要认知**：你日常使用的通义千问、豆包、ChatGPT等，都是**基于大模型开发的应用**，而非大模型本身。它们额外实现了会话记忆、联网搜索、文件上传等功能。

大模型在部署时通常都会对外暴露**基于HTTP协议的API接口**，我们可以用任何自己喜欢的方式调用该接口，实现与大模型的交互。

这里的传统应用，你可以简单理解为 python 代码。

| **维度** | **训练大模型** | **调用大模型（本课程定位）** |

## 5. 实战：从零搭建聊天机器人

### 5.1 阶段一：单次对话机器人

**目标**：发送一条消息，获取大模型的一次回复，验证API调用链路通畅。

```plain
# 1. 导入必要的库
from openai import OpenAI

# 2. 初始化大模型客户端
# 以百度AI Studio兼容接口为例
client = OpenAI(
    api_key="你的API_Key",                          # 替换为你的真实Key
    base_url="https://aistudio.baidu.com/llm/lmapi/v3"  # 百度AI Studio接口
)

# 3. 调用API获取回复
response = client.chat.completions.create(
    model="ernie-4.5-0.3b",                         # 模型名称（百度文心轻量版，免费额度充足）
    messages=[
        {"role": "system", "content": "你是一个友好的AI助手，回答简洁明了"},  # 系统指令
        {"role": "user", "content": "请介绍一下自己，一句话即可"}              # 用户输入
    ]
)

# 4. 解析并输出结果
ai_reply = response.choices[0].message.content
print(f"AI助手：{ai_reply}")
```

**代码要点解析**：

| **组件** | **作用** |
| --- | --- |
| <span style="background-color:#f7f6f3">api\_key</span> | 身份凭证，证明你有权调用模型 |
| <span style="background-color:#f7f6f3">base\_url</span> | 大模型服务的访问地址 |
| <span style="background-color:#f7f6f3">model</span> | 指定使用哪个模型（不同模型能力不同） |
| <span style="background-color:#f7f6f3">messages</span> | 对话上下文，<span style="background-color:#f7f6f3">system</span>定义AI角色，<span style="background-color:#f7f6f3">user</span>是用户输入 |

通常消息的角色有三种：

| **角色** | **描述** | **示例** |
| --- | --- | --- |
| **system** | 优先于user指令之前的指令，也就是给大模型设定角色和任务背景的系统指令 | 你是一个乐于助人的编程助手，你以小团团的风格来回答用户的问题。 |
| **user** | 终端用户输入的指令（类似于你在ChatGPT聊天框输入的内容） | 写一首关于Java编程的诗 |
| **assistant** | 由大模型生成的消息，可能是上一轮对话生成的结果 | 注意，用户可能与模型产生多轮对话，每轮对话模型都会生成不同结果。 |

其中System类型的消息非常重要！影响了后续AI会话的行为模式。

比如，我们会发现，当我们询问这些AI对话产品“**你是谁**”这个问题的时候，每一个AI的回答都不一样，这是怎么回事呢？

### 5.2 阶段二：多轮对话机器人（带记忆功能）

这里还有一个问题：

大模型的API接口是"**无状态**"的，服务端不会记录用户请求的上下文。因此我们调用API接口与大模型对话时，每一次对话信息都不会保留，多次对话之间都是独立的，没有关联的。

因此大模型并不知道之前的聊天历史，也就是说**大模型是没有记忆**的。

**解决方法**：把历史消息都放入Messages中，形成一个数组，实现连续交互，让AI能记住之前的对话内容。

```plain
from openai import OpenAI

# 1. 初始化客户端
client = OpenAI(
    api_key="你的API_Key",
    base_url="https://aistudio.baidu.com/llm/lmapi/v3"
)

# 2. 对话历史（AI的“记忆”）
messages = []

print("=== AI聊天机器人已启动 ===")
print("输入'退出'结束对话\n")

# 3. 循环对话
while True:
    # 获取用户输入
    user_input = input("你：")
    
    # 判断退出
    if user_input == "退出":
        print("AI：再见！")
        break
    
    # 把用户消息加入记忆
    messages.append({"role": "user", "content": user_input})
    
    # 调用大模型
    response = client.chat.completions.create(
        model="qwen-turbo",
        messages=messages
    )
    
    # 获取回复并输出
    reply = response.choices[0].message.content
    print(f"AI：{reply}\n")
    
    # 把AI回复也加入记忆
    messages.append({"role": "assistant", "content": reply})
```

**多轮对话原理**：

- <span style="background-color:#f7f6f3">messages</span>列表存储了完整的对话历史
- 每次调用API时，将整个历史发送给模型
- 模型基于全部历史生成回复，从而“记住”前面的内容

## 6. 一些常见的符号

### 模型参数大小

- **K** = 千
- **M** = 百万
- **B** = 十亿（最常用，如7B = 70亿参数）
- **T** = 万亿

### 上下文窗口

- **8K / 32K / 128K** 中的 **K** = 千字符
- 代表AI一次能“记住”多少文字
- 1个汉字 ≈ 2个Token

### 一句话分清

- **B**：模型聪不聪明（参数量）
- **K**：记性好不好（上下文窗口长度）

### 模型命名规则

格式：**系列名 + 版本号 + 参数量 + 用途标签**

示例：

- <span style="background-color:#f7f6f3">Qwen2.5-7B-Instruct</span>：Qwen系列，2.5版本，70亿参数，对话指令专用
- <span style="background-color:#f7f6f3">Qwen-turbo</span>：Qwen极速特供版（云端不标参数）
- <span style="background-color:#f7f6f3">ernie-4.5-0.3b</span>：文心系列，4.5版本，3亿参数
